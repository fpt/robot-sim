# reflex_quad アクチュエーション設計と Isaac 評価計画

作成: 2026-09-02 / 前提ドキュメント: reflex_quad_12dof_trot_plan.md

## 1. サーボ選定: 全12軸 Feetech STS3215 で統一

### 要求(simアーキテクチャの実機再現)

sim は implicit drive を切り servo_model.py が唯一の位置ループ。実機で同型を
組むための要件:

1. **制御モード選択**: 内蔵位置ループを切り PWM デューティ/電流を直接指令
   できること(STS の PWM オープンループモードで充足)
2. **ゲイン実行時書き換え**: 内蔵ループ使用時もソフト着地のため PID レジスタを
   動作中に書けること
3. **電流テレメトリ**: 読めること+分解能とノイズ床(研究の中心観測)
4. **バス帯域**: 12軸 × 100 Hz の sync read/write

### STS3215 が満たすもの

- フル TTL コマンドセット+レジスタマップ公開、OSS の Python/C ライブラリ
- 位置・速度・負荷・電圧・電流・温度のフィードバック
- 12bit 磁気エンコーダ(4096 step、0.088°/step)、デッドバンド 10 count ≈ 0.9°
- 19 kg·cm @7.4V(≈1.9 Nm) — tau_max 1.6 Nm に対し充足
- 約 $29/軸(国内では秋月で入手可)。SO-ARM100/LeRobot 系で情報・入手性が突出
- 熱保護 ~70°C でトルクカット → 連続高負荷保持はデューティ管理が必要

### ロール/ヨー軸をホビーサーボにしない理由(検討済み・却下)

- ロール軸は t_avail ≈ 0.3 s の窓で傾きレートを打ち返す**最も帯域を要求する軸**。
  ホビー PWM は 50 Hz(20 ms 周期)で制御 100 Hz の半分しか指令できない
- ロール電流=横方向不均衡トルク、ヨー電流=足先滑り・推進負荷の直接観測。
  ホビーサーボ化はこの 2 チャネルを失い、感度掃引で最も不確かな量(接地摩擦)
  を実機でも盲目にする
- 05_fault / 07_self_check の電流ベース故障監視に構造的死角を 4 つ作る
- sim のサーボモデルが「同定不能な内蔵ループ」の二重実装になる
- 節約額は 4 軸で計 $50 前後 — 上記の代償に見合わない

### 分離境界の設計判断

サーボ内蔵エンコーダは**サーボ(ローレベルドライバ)のためのもの**とし、
コントローラの観測には入れない。sim でも servo_model.py は内部で q を読む
(禁止はコントローラが q を見ること)。境界はハードウェアではなく
コントローラモジュールに置く。

## 2. 足先位置の IMU 推定(observer.py 拡張)

平面接地・スタンス中は構造的にほぼ可観測:

- 足IMU×胴体IMUの重力方向差 → 足リンクの相対 pitch = f(q_hip + q_knee)、
  ドリフトなし
- 静力学 τ = J(q)ᵀF(電流2本 + FSR1本/脚)が q への追加拘束
- 接地足の共平面拘束(FSR が適用可否を教える)
- 指令位置を事前分布に(support.py と同じ扱い)
- 12DOF 化で足の相対姿勢が 3D になり、片側フレームで未知数6 vs 観測6

**限界**: スイング中は接地拘束・静力学が消え、体動加速度が重力方向を汚す。
一番位置が欲しい遊脚搬送中に一番弱い → **サーボ代替にはならない**。

**用途**(spec section 43 の本線に乗る):
- 指令位置のサグ/デッドバンド/バックラッシ補正 → support.py 荷重解の入力改善
- 指令由来 vs IMU 由来の乖離 = 新しい故障残差(finding 11 の死角 B/C への追加)
- 推定残差の増大 = 平面仮定の破れ検出(不整地対応の入口)

## 3. 着地衝撃(反動)の扱い: 時間スケールで分業

ピーク力 F ∝ v_td·√(k·m_eff)。m_eff はギア比²のロータ反射慣性が支配し、
制御モードによらず消えない。最初の 1〜数 ms に 100 Hz ループは原理的に
間に合わない。

| 時間帯 | 手段 | 実装 |
|---|---|---|
| 0–数 ms | **足裏パッド(受動)** | ゴム/発泡材で k を桁で下げ、衝撃を 10 ms 級に伸ばして制御と FSR の見える時間スケールに入れる。剛足だと FSR がスパイク1サンプルになり荷重観測が死ぬ — パッドは**FSR のアンチエイリアスフィルタ**でもあり二重に必須 |
| 〜10 ms | トルクリミットレジスタ | スリップクラッチとして衝撃トルクをクリップ(ギア保護兼用) |
| 10 ms〜 | **プリソフト化** | FSR を待たず軌道計画から接地 1–2 tick 前に膝ゲインを低下、着地後に復帰。事前準備ならループ遅延は無害 |
| 全域 | 着地速度の削減 | 台形軌道(速いスイング+最後だけ減速)。t_avail 予算内で組めるかは幾何層で計算 |

補助: 電流スパイクを FSR と二重化した接地検出に使う(finding 12 の接触状態
推定の頑健化)。膝を曲げた姿勢で着地(伸び切りは構造直撃、曲げはトルクで
受かるのでクラッチとゲインが効く)。

## 4. トロットのヨー反作用キャンセル

### 力学

対角スイング(FL前出し+RR後出し)の反作用は、オフセットの符号が揃うため
**同方向(左回り)に加算**される。半サイクルごとに反転する歩容周波数
(2–3 Hz)のヨー振動。

### 制御(2層)

- **フィードフォワード(主役)**: 外乱源が自分の指令なので、遊脚質量分布と
  指令軌道から L_z(t) を事前計算できる。前後ヨーの推進プロファイル(逆位相)
  に**コモンモード補正**を重畳し、フレーム+背骨に逆向き角運動量を持たせる
  (歩行時の腕振り/チーターの尻尾と同原理、追加ハード無し)
- **オンライン較正**: 実スイングレートは遊脚の**足IMUジャイロ**で測れる
  (finding 8 の実証済みチャネル)→ サーボのサグによる FF 振幅誤差を補正
- **フィードバック**: 残差は胴体ジャイロ ω_z に直接見える(可観測性は最良)。
  ω_z → 0 の PI をヨー指令トリムに追加

### 残差の行き先と成立条件

打ち消し残差は接地対角 2 点の**摩擦カップル**が受ける。キャンセルが効くほど
接地摩擦要求が下がる = 摩擦係数に対する結論の頑健性が上がる(sim-real 移送に
直結)。指標 **yaw_slip_margin** = 要求接線力/法線力 の μ に対する余裕を
criteria に追加。

### 注意: ヨー軸は推進とキャンセルの二役

可動域 ±30° と速度予算を分け合う。幾何層で「推進ストロークを削らず
キャンセル振幅が確保できるか」を先に確認。不足時の逃げ: 対角 2 脚の
スイング位相差、加速を寝かせた軌道形状(ロール軸は鉛直角運動量に寄与
できないので頼れない)。

## 5. Isaac Sim で評価すべきこと(mock で済むことと分けて)

原則: **Isaac の役割は「mock が描いた成立領域の抜き取り検査」+
「接触だけが持つ物理」**。以下の順に。

### 5.1 Isaac でしか評価できないもの(本命)

| # | 評価項目 | 実験 | 合否指標(criteria 案) |
|---|---|---|---|
| I-1 | **着地衝撃の実相**: パッド剛性 k を変えた時のピーク力・バウンド | 単発対角スイング+着地 | peak_force / bounce_count / FSR 立ち上がり時間 |
| I-2 | **プリソフト化の効果** | I-1 のゲイン低下 有/無 | 着地後整定時間、姿勢乱れ角 |
| I-3 | **ピボット摩擦とヨー推進**: 接地足の旋回滑り・横滑り | ヨー逆位相推進を静止歩容で | 前進量/サイクル(幾何層予測比)、足先滑り距離 |
| I-4 | **ヨー反作用キャンセル**: FF×FB の 2×2 | トロット 1〜数サイクル | ω_z 残差 RMS、yaw_slip_margin |
| I-5 | **回復可能包絡 θ_max の実接触版** | 傾きを与えて着地→回復 | mock 実測値との差 |
| I-6 | **摩擦感度掃引** | I-3/I-4 を μ±50% で | 結論(成立/不成立)が反転しないか |

注意: Isaac 標準の剛体接触は衝撃が非現実に硬く出る。compliant contact 設定
またはパッドの明示モデル化が必要で、その較正は**ベンチ実測**(パッド+FSR に
重り落下)から取る。「接触の絶対値は信じない」ルールの適用対象。

### 5.2 mock で先に済ませるもの(Isaac に持ち込まない)

- 転倒時定数マップ、外乱錐、可動度計算、L_z(t) と FF 振幅の解析計算(幾何層)
- θ_max の初回実測、FF/FB の制御ロジック検証、e_twist の状態依存切り替え
- IMU 足先推定器の真値比較(spec 43) — truth.csv 比較インフラは mock で十分

### 5.3 sim に入れるべき STS3215 実測値(servo.yaml 差し替え、memo 49)

**購入は 1 個先行**し、ベンチで以下を測って sim に逆輸入してから 12 個発注:

1. **電流テレメトリのノイズ床と分解能** — finding 11 の検出余裕
   (sim で 0.038 A vs 床 0.037 A)が実機で成立するかの占い。最優先
2. トルク–速度直線(負荷時速度) — 幾何層のサーボ合否等高線に重ねる実測値
3. デッドバンド・バックラッシの実測(公称 0.9° の確認)
4. PWM オープンループモードの電圧→トルク特性と遅延
5. sync read/write の 12 軸想定バス周回時間(実効レイテンシ、100 Hz 成立確認)
6. ゲイン/トルクリミットレジスタ書き換えの反映遅延(プリソフト化の粒度)
7. 熱: 想定デューティでの温度上昇カーブ(70°C トルクカットまでの余裕)

## 6. STS3215 の使い方(モード運用方針)

- **基本**: PWM オープンループモード+ホスト側 servo_model.py 100 Hz
  (sim と同型)。内蔵エンコーダはローレベル保護と較正専用、コントローラの
  観測に入れない
- **ソフト着地**: ホスト PD ゲインのスケジューリング(接地 1–2 tick 前に低下)
  +トルクリミットレジスタの常時クリップ
- **電流の用途**: (a) 姿勢系 — ロール電流=横不均衡、ヨー電流=推進/滑り負荷、
  (b) 故障監視 — current_dynamic(finding 10)、(c) 接地検出の FSR 二重化
- **バス**: TTL 1 Mbps、12 軸 sync read/write。100 Hz は成立見込みだが余裕は
  薄い — 5.3-5 の実測で確定。ゲイン切替は 1 tick(10 ms)粒度が乗る前提で設計
- **熱管理**: ロール軸は胴体モーメントを常時保持 → デューティ最大。
  スタンス幅と体高の選定に 5.3-7 の熱カーブを反映

  乱さないかの解析 — 幾何層 (b) の拡張
- STS3215 の PWM モードにおける電流テレメトリの有効性(位置モードと同精度か)
  — ベンチ測定項目に含める
